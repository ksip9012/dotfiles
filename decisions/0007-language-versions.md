# 0007. 言語の版は Python を最新の 1つ前、Go・Rust を最新のマイナー版にし、ひな形は毎年 11月に上げる

- Status: Accepted
- Date: 2026-11-03（Go を 2026-11-07、Rust を 2026-11-11 に足した）

## Context
ひな形（`templates/python/`）の版は、ルールに沿って選んだものではなく、既にあった設定を写したものだった。2026-11-03 時点で Python 3.13（最新は 3.15）、uv 0.11.8（最新は 0.13.6）と、どちらも 2つ前の版になっていた。

mise で入れる言語や道具の版は Dependabot の対象外なので、古くなっても知らせが来ない。一方で、`~/Documents/codes/` のリポジトリには、2年近く触っていないものもある。

Go のひな形（`templates/go/`）を作るとき（2026-11-07）、1 をそのまま当てると困ることがわかった。Go は半年ごと（2月と8月）に新しい版が出て、新しい版が 2つ出るとサポートが終わる（https://go.dev/doc/devel/release ）。2026-11-07 時点で最新は 1.27（2026-08-19）、1つ前は 1.26（2026-02-10）。1.26 にすると、2027年2月に 1.28 が出た時点でサポートが終わり、次に上げる 11月まで約 9か月、新しいプロジェクトをサポートの切れた版で始めることになる。

Rust のひな形（`templates/rust/`）を作るとき（2026-11-11）、同じことを考えた。Rust は 6週ごとに新しい版が出て、サポート（不具合や脆弱性の修正）があるのは最新の stable だけ（一般的な理解。2026-11-11 には公式のページで確かめていない）。2026-11-11 時点で最新は 1.99（1.99.1 は 2026-10-13）。1つ前にすると、作った日からサポートの切れた版になる。

## Decision
1. 言語は、最新の 1つ前のマイナー版にする（2026-11-03 は Python 3.14）。ただし Go と Rust は最新のマイナー版にする（2026-11-07 は Go 1.27、2026-11-11 は Rust 1.99）
2. `mise.toml` にはマイナー版までを書き、細かい版（パッチ）は固定しない
3. ひな形は、毎年 11月（Python の新しい版が 10月に出たあと）に、言語と道具（uv など）の版を上げる。Go と Rust も同じ 11月に上げ、1つの Issue → PR にまとめる
4. 既存のリポジトリは、次に触るとき、または指摘が入ったとき（Dependabot、CI が落ちた、ライブラリが古い版の対応をやめた、など）に上げる。一斉にひな形の形へ置き換えることはしない。触るときに github-init で足りないものを足す

## Consequences
- 最新の版は、ライブラリが追いつくまで少し時間がかかることがあるので、1つ前にすると対応していないライブラリに当たりにくい（一般的な傾向）
- 細かい版は入れるたびに最新になるので、手元と CI でずれることがある。困ったら mise の lock ファイル（`mise.lock`）に移る。`jdx/mise-action` は lock ファイルがあれば `--locked` で入れる
- ひな形を上げると、dotfiles の CI（python template）が GitHub 上で新しい版で動くかを確かめる
- 既存のリポジトリはひな形とずれていくが、置き換えの手間は触るときだけにかかる。見せる作品（`personal-products/`）は、見せる前に置き換えるかを考える
- Python の版を書くのは `mise.toml` と `requires-python` の 2か所。pyright の `pythonVersion` は書かず、仮想環境の Python から読ませる
- Go を最新にしても、ライブラリに当たりにくくなるという 1つ前の利点はあまり失わない。Go 1 の互換の約束で、新しい版で古いコードが動かなくなることがほとんどないため（一般的な傾向）
- Go のサポートが切れるのは、8月に新しい版が出てから 11月に上げるまでの約 3か月だけになる（2027年なら 1.29 が出たあと。出る月は今までの間隔からの見込み）。Go の新しい版が出るたび（3月と 9月）に上げればなくせるが、年 1回の作業が年 3回になるので選ばなかった
- Go の版を書くのは `mise.toml` の `[tools]` と `go.mod` の `go` の行（最低限必要な版。`1.27.0` の形）の 2か所。`toolchain` の行は書かず、使う版は mise だけで決める
- Rust は、最新に固定しても次の版が出る 6週後にはサポートが切れる。11月に上げても 1年のほとんどはサポート外の版になる。それでも `stable`（いつも最新）にせず版を固定するのは、clippy が版ごとに警告を足すので、`stable` だと手元のコードを変えていなくても、ある日 CI が急に落ちるため。固定すれば手元と CI の版もそろう。サポート外になっても、Rust は版をまたいだ互換を約束していて、上げるときに困ることはほとんどない（一般的な傾向）
- Rust の版を書くのは `mise.toml` の `[tools]` と `Cargo.toml` の `rust-version`（最低限必要な版。`1.99` の形）の 2か所。`rust-toolchain.toml` は置かず、使う版は mise だけで決める（mise が `RUSTUP_TOOLCHAIN` を設定するので、置いても mise の版が勝つ）
